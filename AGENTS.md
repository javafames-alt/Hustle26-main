# Правила для AI-агентов (Codex и Notion AI)

Над проектом работают два агента:

- **Codex** — работает локально на компьютере владельца, меняет файлы в рабочей папке.
- **Notion AI** — работает напрямую с GitHub через API, локальной копии у него нет.

Общая точка — этот репозиторий на GitHub. Всё, что не запушено, второй агент не видит.

## Codex: всегда синхронизируй и коммить сразу

1. **Перед началом любой задачи** забери свежие изменения:
   ```
   git pull --rebase origin main
   ```
   Если есть незакоммиченные изменения — сначала закоммить их (см. п. 3), потом `pull`.
2. **Сделал изменение — сразу проверь сборку:**
   ```
   .\gradlew.bat build -x check
   ```
3. **Сборка прошла — сразу закоммить и запушь всё, не спрашивая:**
   ```
   git add -A
   git commit -m "<что сделано, кратко>"
   git push origin main
   ```
   Не оставляй изменения только локально.
4. **Если push отклонён** (в GitHub появились новые коммиты):
   ```
   git pull --rebase origin main
   ```
   При конфликте сохрани обе версии изменений, проверь сборку и снова сделай `push`.
5. **Никогда не используй `git push --force`** и не переписывай историю `main` — это удалит коммиты Notion AI.

## Команды владельца

- **«скачай» / «обнови» / «подтяни»** — `git pull --rebase origin main`, чтобы в локальных исходниках были все изменения с GitHub (в том числе от Notion AI). После этого коротко перечисли, что пришло.
- **«закоммить» / «запушь»** — `git add -A`, коммит с понятным сообщением, `git push origin main`.
- **«скачай ветку X»** — `git fetch origin` и `git checkout X`.

## Notion AI

- Работает в ветках `notion/<задача>` и открывает Pull Request в `main`.
- Мёржит только после ✅ от CI.
- Если Notion AI смёржил PR — Codex должен сделать `git pull --rebase origin main` перед следующей задачей.

## CI

`.github/workflows/build.yml` собирает проект при каждом push в `main` и в каждом PR (Java 25, `./gradlew build -x check`). В PR результат публикуется комментарием ✅/❌.

## Нельзя коммитить

Токены, пароли, ключи, `.env`, `build/`, `.gradle/`, `run/`, `logs/` (уже в `.gitignore`).
